# 앱 빌드와 배포

이 저장소는 **하나의 소스에서 웹과 앱을 모두** 만듭니다. 화면 코드는 한 벌이고,
갈라지는 것은 빌드 설정과 몇 군데의 환경 분기뿐입니다.

| | 웹 | 앱 (Android / iOS) |
| --- | --- | --- |
| 명령 | `npm run build` | `npm run build:app` |
| 결과물 | 서버가 있는 Next 앱 | `out/` 정적 파일 → 네이티브 셸에 동봉 |
| 상세 주소 | `/policy/123` (검색 유입) | `/policy/detail?id=123` |
| sitemap · 공유 카드 | 있음 | 없음 (필요 없음) |

---

## 왜 이런 구조인가

### 앱에는 서버가 없다

앱은 WebView 안에서 **번들에 동봉된 파일**을 엽니다. 서버에서 화면을 받아오지 않습니다.
비행기 모드에서도 앱이 뜨고, "웹사이트를 감싸기만 한 앱"으로 심사에서 걸리지 않기 위한
전제이기도 합니다.

서버가 없으니 정적 export 가 필요하고, 정적 export 는 `[id]` 에 들어갈 값을 빌드 시점에
전부 알아야 합니다. 게시글·지원금 id 를 미리 알 수 없으므로 앱에서는 쿼리로 받습니다.

### 그렇다고 `/policy/123` 을 없앨 수는 없다

`sitemap.xml` 이 싣는 주소이고, 이 서비스에서 검색 유입 가치가 가장 큰 문서입니다.
그래서 **두 주소가 같은 화면 컴포넌트를 렌더**하고, 앱 안에서의 이동은 언제나
`src/utils/routes.ts` 를 거쳐 쿼리 쪽으로 갑니다.

경로를 문자열로 직접 쓰지 마세요. 템플릿 문자열이 호출부에 흩어지면 라우트 구조를 바꿀 때
무엇이 깨졌는지 grep 으로도 잡히지 않습니다.

### 웹 전용 라우트는 확장자로 걸러낸다

`*.web.tsx` 는 앱 빌드에서 통째로 빠집니다 (`next.config.ts` 의 `pageExtensions`).
이미 쓰고 있던 `*.dev.tsx`(개발 서버 전용) 규약을 그대로 넓힌 것입니다.

메타데이터 파일(`sitemap` · `robots` · `manifest` · `opengraph-image`)은 **파일 이름 자체가
규약**이라 이 방법이 통하지 않습니다. 이름을 바꾸면 라우트는 생기지만 GET 핸들러로
이어지지 않아 405 가 됩니다. 대신 `force-static` 으로 고정했습니다.

그중 `policy/[id]/opengraph-image.tsx` 하나는 그 방법도 통하지 않습니다 — 동적 세그먼트의
OG 이미지는 정적 export 와 양립하지 않습니다. 카카오톡에서 지원금 링크를 펼쳤을 때 제목이
보이는 카드라 웹에서는 버릴 수 없어, `scripts/build-app.mjs` 가 **앱 빌드 동안만** 비켜
두었다가 되돌립니다. 빌드가 실패해도 `finally` 에서 원복하므로 작업 트리에 흔적이 남지
않습니다.

## 개발 흐름

```bash
npm ci
cp .env.example .env.local     # NEXT_PUBLIC_API_URL 을 백엔드 주소로

npm run dev                    # 웹 개발 서버 (앱 화면도 여기서 대부분 확인됩니다)

npm run build:app              # 정적 파일 out/ 생성
npm run app:sync               # build:app + 네이티브 프로젝트로 복사
npm run app:android            # app:sync + Android Studio 열기
npm run app:ios                # app:sync + Xcode 열기 (맥에서만)
```

웹 코드만 고쳤다면 `app:sync` 후 다시 빌드하면 됩니다. 네이티브 설정(권한·플러그인)을
고쳤다면 Android Studio / Xcode 에서 다시 빌드해야 합니다.

## Android 빌드

### JDK 21이 필요합니다

Capacitor 8 은 source release 21 을 요구합니다. 17 이면 `invalid source release: 21`,
Android Studio 번들 JDK(25)면 Gradle 이 `Unsupported class file major version 69` 로
거부합니다. **21만 됩니다.**

```bash
export JAVA_HOME="/path/to/jdk-21"
cd android && ./gradlew assembleDebug
```

`android/local.properties` 에 SDK 위치가 필요합니다(이 파일은 커밋되지 않습니다).

```properties
sdk.dir=C:/Users/<이름>/AppData/Local/Android/Sdk
```

### 결과물

| 명령 | 결과 | 용도 |
| --- | --- | --- |
| `./gradlew assembleDebug` | `app/build/outputs/apk/debug/app-debug.apk` | 기기·에뮬레이터 확인 |
| `./gradlew assembleRelease` | `.../apk/release/app-release.apk` | 사이드로드 배포 |
| `./gradlew bundleRelease` | `.../bundle/release/app-release.aab` | **구글 플레이 업로드** |

## iOS 빌드 (맥에서)

Capacitor 8 은 CocoaPods 대신 Swift Package Manager 를 쓰므로 윈도우에서도 프로젝트 생성과
자산 복사는 됩니다. 다만 **빌드·서명·제출은 맥의 Xcode 에서만** 할 수 있습니다.

```bash
npm ci
npm run app:ios          # Xcode 가 열립니다
```

Xcode 에서 할 일:

1. `App` 타깃 > Signing & Capabilities 에서 팀 선택
2. **Push Notifications** capability 추가 (없으면 푸시 토큰이 발급되지 않습니다)
3. Background Modes > Remote notifications 확인 (`Info.plist` 에 이미 들어 있습니다)
4. Product > Archive → Distribute App

## 자격증명 넣기

아래 파일들은 저장소에 없습니다. 각 콘솔에서 받아 제자리에 두면 그때부터 동작합니다.

### Firebase (푸시)

| 파일 | 위치 |
| --- | --- |
| `google-services.json` | `android/app/` |
| `GoogleService-Info.plist` | `ios/App/App/` (Xcode 에서 타깃에 추가) |

Android 는 파일이 있으면 `google-services` Gradle 플러그인이 **자동으로** 켜집니다
(`android/app/build.gradle` 하단). 없으면 빌드는 되고 토큰 발급만 실패합니다.

iOS 는 추가로 Firebase 콘솔에 **APNs 인증 키(.p8)** 를 등록해야 합니다. 이게 없으면
토큰은 나오는데 알림이 오지 않습니다.

> 서버는 FCM 으로 쏩니다(`PushNotificationSender`). 그래서 앱도 APNs 원시 토큰이 아니라
> **FCM 등록 토큰**을 서버에 올립니다. 이 때문에 `@capacitor/push-notifications` 대신
> `@capacitor-firebase/messaging` 을 씁니다.

### 카카오 로그인

앱 쪽에 넣을 키는 없습니다. 서버가 인가 URL 을 만들고 코드를 교환하기 때문입니다.
대신 아래가 전제입니다.

- 웹이 배포돼 있고, 그 주소가 카카오 콘솔의 **Redirect URI** 로 등록돼 있을 것
- 서버의 `KAKAO_REDIRECT_URI` 가 그 주소일 것

앱 로그인 흐름은 이렇습니다.

1. 앱이 인가 URL 에 `state=app` 을 붙여 **시스템 브라우저**로 엽니다
2. 카카오가 로그인 후 서버에 등록된 redirect_uri(웹 콜백)로 보냅니다. `state` 는 그대로 옵니다
3. 웹 콜백 화면이 `state=app` 을 보고, 토큰 대신 인가 코드만 `com.carecode.app://oauth/kakao` 로 넘깁니다
4. 앱이 딥링크로 열리고, 기존 콜백 화면에 코드를 넘겨 평소대로 끝냅니다

WebView 안에서 열지 않는 이유: **카카오가 인앱 브라우저 로그인을 막고**, 애플도 OAuth 를
외부 브라우저에서 처리하도록 요구합니다. `state` 를 쓰는 이유: 서버가 만드는 인가 URL 에
`state` 가 없고 카카오는 받은 값을 그대로 돌려주므로, **서버도 카카오 콘솔도 고치지 않고**
앱에서 온 로그인을 구분할 수 있습니다.

### 백엔드 주소

앱은 서버가 없으므로 `NEXT_PUBLIC_API_URL` 이 **빌드 시점에 박힙니다.** 주소가 바뀌면 다시
빌드해서 다시 올려야 합니다.

백엔드의 CORS 허용 목록에 WebView 의 출처가 있어야 합니다.

```
https://localhost        # Android
capacitor://localhost    # iOS
```

이 둘은 **백엔드 기본값에 이미 들어 있습니다**(`CorsPolicy.DEFAULT_ALLOWED_ORIGINS`).
다만 `CORS_ALLOWED_ORIGINS` 환경변수로 목록을 통째로 덮어쓰는 배포라면, 그 값에도 두 출처를
직접 넣어야 합니다 — 빠지면 앱은 켜지는데 아무 데이터도 나오지 않습니다.

## 릴리스 서명 (Android)

구글 플레이에 올리는 파일은 서명돼 있어야 하고, **같은 키로 계속 서명해야 합니다.**
키를 잃으면 그 앱을 다시는 업데이트할 수 없습니다.

```bash
keytool -genkeypair -v \
  -keystore carecode-release.jks \
  -alias carecode \
  -keyalg RSA -keysize 2048 -validity 10000
```

만든 뒤 `android/keystore.properties.example` 을 `keystore.properties` 로 복사해 채웁니다.
CI 에서는 환경변수(`CARECODE_KEYSTORE_PATH` 등)로도 받습니다.

키스토어와 `keystore.properties` 는 `.gitignore` 에 있습니다. **절대 커밋하지 마세요.**
비밀번호는 키 파일과 함께 비밀번호 관리자에 보관하세요.

## 앱에서만 다르게 도는 것

고칠 때 "웹에서도 괜찮은가" 를 함께 봐야 하는 자리들입니다.

| 무엇 | 웹 | 앱 | 코드 |
| --- | --- | --- | --- |
| 리프레시 토큰 | HttpOnly 쿠키 | Keychain / EncryptedSharedPreferences | `src/apis/session.ts` |
| 푸시 | 브라우저 Notification + 서비스 워커 | 네이티브 FCM | `src/apis/pushNative.ts` |
| 카카오 로그인 | 현재 창 이동 | 시스템 브라우저 + 딥링크 | `src/apis/kakaoAppAuth.ts` |
| 화면 폭 | `max-w-sm` 목업 | 기기 폭 전체 | `globals.css` 의 `html[data-native]` |
| 뒤로 가기 | 브라우저 | 하드웨어 버튼 | `src/components/common/AppBootstrap.tsx` |
| 밖으로 나가는 링크 | 새 탭 | 인앱 브라우저 | `src/utils/externalLink.ts` |
| 연결 끊김 | 브라우저 이벤트 | 네이티브 연결 상태도 함께 | `src/hooks/useOnlineStatus.ts` |

**리프레시 토큰이 앱에서 다른 이유**가 가장 중요합니다. WebView 의 출처는
`https://localhost`(Android) / `capacitor://localhost`(iOS) 라서 API 서버로 가는 쿠키가
**서드파티 쿠키**가 되고, iOS WKWebView 는 이를 기본 차단합니다. 쿠키에 기대면 iOS 에서
로그인이 유지되지 않습니다.

서버는 갱신할 때마다 리프레시 토큰을 **교체**합니다. 새 토큰을 저장하지 못하면 다음 갱신이
실패해 사용자가 로그아웃됩니다. 그래서 저장을 기다립니다(`void` 로 던지지 않습니다).
